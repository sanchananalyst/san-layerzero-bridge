# Governance Change Monitoring Specification

## Purpose and operating model

Monitoring must detect any privileged change quickly enough to pause the
counterparty chain before additional exposure. It is defense in depth, not an
authorization control. Phase 5A.5 defines the specification only; it does not
deploy monitoring infrastructure.

Use independently operated finalized RPC/indexing paths and retain raw event or
account data, decoded values, slot/block, blockhash, transaction identity, and
the approved-state version. Event detection must always be followed by direct
state read-back; absence of an event is not proof that state is correct.

Severity meanings:

- **CRITICAL:** plausible backing/custody or complete governance compromise;
  page immediately and pause the counterparty chain.
- **HIGH:** bridge safety or availability control changed; page immediately,
  block activation, and normally pause both sides.
- **MEDIUM:** governance composition or expected operational activity changed;
  investigate before any further governance action.

## Alert handling and correlation

Every alert opens an incident record with a unique identifier. The responder
must classify the transaction as approved, unexpected, or unresolved by
comparing the complete proposal hash and decoded calls/instructions—not by
recognizing the signer address alone.

Correlate any governance drift with packets, supply, Store TVL, escrow balance,
in-flight inventory, and rate-limit consumption. Two simultaneous changes, a
change followed by an unexpected message, RPC disagreement, missing finalized
data, or a monitor gap upgrades the incident to CRITICAL.

An expected change remains open until two independent finalized read-backs match
the approved after-state. An unexpected change never becomes accepted merely
because the checker configuration is edited to match it.

## Readiness gate and drills

Before Phase 5B, each row must have a named primary and backup owner, tested
paging route, maximum response time, two independent data providers, retained
evidence destination, and a completed tabletop plus read-only replay drill.
Monitoring must run during the entire handoff and activation windows. Any blind
spot, stale approved-state manifest, or failed page keeps the gate closed.
